# MySQL 面试复习路线

## 1. 复习目标

这套笔记面向 Java 后端 MySQL 面试，重点不是完整覆盖所有数据库知识，而是形成下面四种能力：

```text
基础题能快速给出准确结论
  -> 原理题能讲清内部机制
  -> SQL 题能现场写出并解释
  -> 场景题能给出排查证据和落地方案
```

默认基于 MySQL 8.x 和 InnoDB。遇到版本相关问题时，应先向面试官确认 MySQL 版本，不要把旧版本结论机械套用到所有环境。

## 2. 六阶段路线

| 阶段 | 主题 | 面试目标 | 建议时间 |
|---|---|---|---|
| [阶段一：SQL 与字段基础](./01-SQL与字段基础.md) | 查询语义、连接、聚合、数据类型 | 基础题回答准确，避开常见陷阱 | 2 天 |
| [阶段二：索引与执行计划](./02-索引与执行计划.md) | B+Tree、联合索引、回表、EXPLAIN | 能判断索引是否有效并解释原因 | 3 天 |
| [阶段三：事务、MVCC 与锁](./03-事务MVCC与锁.md) | ACID、隔离级别、版本链、行锁 | 能解释一致性、阻塞与死锁 | 3 天 |
| [阶段四：InnoDB 与日志](./04-InnoDB与日志.md) | Buffer Pool、Redo、Undo、Binlog | 能讲清一行数据的读写与崩溃恢复 | 2 天 |
| [阶段五：SQL 优化与场景题](./05-SQL优化与场景题.md) | 慢 SQL、分页、排序、库存、主从延迟 | 能用证据排查生产问题 | 2 天 |
| [阶段六：SQL 手写与项目表达](./06-SQL手写与项目表达.md) | 高频 SQL、项目案例、追问准备 | 能现场写 SQL 并讲出真实优化案例 | 2 天 |

## 3. 每天的复习方法

```text
20 分钟：不看笔记口述昨天的核心问题
30 分钟：复习当天原理
30 分钟：在 MySQL 中运行 SQL、EXPLAIN 或事务实验
20 分钟：按“结论 -> 原理 -> 示例 -> 边界”录音回答
10 分钟：记录答错、说不清和容易混淆的内容
```

每个知识点至少完成四步：

```text
能够定义
  -> 能举例
  -> 能说明反例或边界
  -> 能承受一到两轮追问
```

## 4. 面试回答模板

### 4.1 原理题

```text
1. 一句话结论
2. 核心数据结构或执行流程
3. 一个具体例子
4. 适用范围、代价或版本差异
```

不要一上来铺大量背景。先回答面试官真正问的内容，再根据追问展开。

### 4.2 场景题

```text
确认现象和影响范围
  -> 收集慢日志、执行计划、监控等证据
  -> 提出可能原因
  -> 逐项验证
  -> 小范围实施优化
  -> 压测并对比结果
  -> 上线后继续观察
```

### 4.3 SQL 题

```text
确认表结构与结果要求
  -> 先写正确结果
  -> 处理 NULL、重复值和并列情况
  -> 再讨论索引和性能
```

## 5. 最低通过标准

完成复习后，应该能够在不看资料的情况下讲清：

1. B+Tree、聚簇索引、回表、覆盖索引和最左前缀原则。
2. `EXPLAIN` 中访问类型、实际扫描行数、排序和临时表。
3. ACID、四种隔离级别、MVCC、Read View 和 Next-Key Lock。
4. Redo Log、Undo Log、Binlog 的分工以及两阶段提交。
5. 慢 SQL 的完整排查流程，而不是只回答“加索引”。
6. 深分页、库存超卖、幂等和主从延迟的典型处理方式。
7. 至少十道 SQL 手写题和一个可以承受追问的真实项目案例。

## 6. 高频问题清单

复习结束后，用下面的问题进行一次 60 分钟模拟面试：

1. 为什么 MySQL 索引常用 B+Tree？
2. 联合索引 `(a, b, c)` 在不同条件下如何生效？
3. 有索引为什么仍可能全表扫描？
4. 覆盖索引和索引下推有什么区别？
5. MySQL 可重复读是怎样实现的？
6. 快照读和当前读有什么区别？
7. 间隙锁什么时候出现，解决什么问题？
8. Redo、Undo、Binlog 各自解决什么问题？
9. 两阶段提交为什么不能省略？
10. 一条 SQL 突然变慢，你如何定位？
11. `LIMIT 1000000, 20` 为什么慢？
12. 如何防止库存超卖并处理重复请求？
13. 如何查询每个部门工资最高的员工？
14. 讲一个你真正参与过的数据库优化案例。
